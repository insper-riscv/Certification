# Certification

🌐 [Português](README.md) · [English](README.en.md)

Certification of the RISC-V RV32IM core with the official ACT4 suite ([riscv-arch-test](https://github.com/riscv/riscv-arch-test)), run in simulation (cocotb/GHDL). This repository runs the suite against the core and reports the result; it never runs on the board.

## 2. Repository Structure

| Path | Contents |
| :--- | :--- |
| `tools/riscv_build/act/rv32im-min/` | Model DUT target on the modular platform: `test_config.yaml`, the UDB YAML, `rvmodel_macros.h`, `link.ld`, and `link-ram.ld` (the variant of the test that rewrites its own code) |
| `tools/riscv_build/act/profile-*/` | One target per core profile (UDB, Sail configuration and `test_config.yaml`), generated by `tools/riscv_build/gen_profiles.py` |
| `tools/riscv_build/act/sim/` | The `act_modular_top` top and the cocotb testbenches that watch the HTIF `tohost` word (`test_act.py` on the RAM bus, `test_act_sdram.py` on the RAM chip) |
| `Insper-RISC-V/` | Submodule with the core, the memories, the peripherals and the simulation tops of the platforms, at the version this repository pins |
| `tools/riscv_build/config.platform-*.yaml` | Configuration of each platform (VHDL sources, top level and memory map), written by `riscv-tools platform sync` from the submodule and never edited by hand |
| `tools/riscv_build/config.modular.yaml` | Modular simulation platform (VHDL sources, top and memory map), written by `gen_profiles.py` and never edited by hand |
| `tools/riscv_build/config.yaml` | Extends `config.modular.yaml` and adds the `act:` section of the minimal target; `config.profile-*.yaml` is the one of each profile without Zifencei, and `config.flash-*.yaml` the one of each profile with Zifencei |

The ACT4 tests, the UDB gems and the `make` come from the image `ghcr.io/insper-riscv/ci-act4:latest`, which carries the ACT4 checkout in `/opt/riscv-foundation/act4/riscv-arch-test` (the environment variable `ACT4_DIR` changes the path). The tests and the gems are always of the same ACT4 commit, which the image records in `/opt/riscv-foundation/act4/.tag` and which every run records in the job summary, in the result and in the notes of the release. The image updates itself every day to the last green commit of ACT4, and this repository pins no version of the suite.

The VHDL comes from the [Insper-RISC-V](https://github.com/insper-riscv/Insper-RISC-V) submodule, which holds the `Core` (the processor), the `Memory` (the memories), the `Peripherals` and the simulation tops of the platforms. The paths in the platform configuration files start with `Insper-RISC-V/`, the folder of the submodule.

## 3. Scope

The certification covers the `I`, `M`, `Zmmul`, `Zicsr`, `Zicntr`, `Zihpm`, `Zifencei`, and `Zicclsm` extensions, listed in `act.extensions` in the configuration. Each of the 120 valid combinations of these extensions over the `I` (60 profiles, 32 registers) and `E` (60 profiles, 16 registers) bases, read from the profile matrix of the Core (`profiles/matrix.yaml`), is a core profile with its own target, generated by `tools/riscv_build/gen_profiles.py`. All of them run on the modular simulation platform, with a 1 MB ROM and RAM. A profile without `Zifencei` runs with `riscv-tools --config tools/riscv_build/config.profile-<name>.yaml certify`, with the memories inside the chip. The profiles with `Zifencei` need the caches (4 kbit) and run with the ROM and the RAM behind them, through `tools/riscv_build/config.flash-<name>.yaml`; the `flash-ram-*` targets run the test that rewrites its own code from the RAM. The details are in [docs/en/act4/platform.md](docs/en/act4/platform.md).

## 4. Running

```bash
git clone --recurse-submodules https://github.com/insper-riscv/Certification.git
cd Certification
uv sync
riscv-tools --config tools/riscv_build/config.yaml certify
```

The tools come from the `ci-act4` image of the [Infra](https://github.com/insper-riscv/Infra) repository: RISC-V GCC, Spike, Sail, GHDL, uv, and Ruby with Bundler and the gems of ACT4's UDB. The automatic flow (`.github/workflows/certification.yml`) certifies the minimal profiles of `tools/riscv_build/minimal_profiles.yaml` on every memory and cache model that the modular top accepts. The two manual workflows, `certification-profiles.yml` (every profile, with a confirmation key) and `certification-profile.yml` (one profile and one model), generate the target at run time. The models, the minimal profiles and the sizing are in [docs/en/act4/matrix.md](docs/en/act4/matrix.md).
