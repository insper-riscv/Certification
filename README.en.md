# Certification

🌐 [Português](README.md) · [English](README.en.md)

Certification of the RISC-V RV32IM core with the official ACT4 suite ([riscv-arch-test](https://github.com/riscv/riscv-arch-test)), run in simulation (cocotb/GHDL). This repository runs the suite against the core and reports the result; it never runs on the board.

## 2. Repository Structure

| Path | Contents |
| :--- | :--- |
| `vendor/riscv-arch-test` | Official suite, pinned as a submodule |
| `tools/riscv_build/act/rv32im-min/` | DUT target: `test_config.yaml`, the UDB YAML, `rvmodel_macros.h`, `link.ld`, and `spike-rv32im-min` (Spike with this target's memory map, used as the reference model) |
| `tools/riscv_build/act/rv32im-sdram/` | Target with the code and the data in the SDRAM, for the extensions that depend on it (Zifencei) |
| `tools/riscv_build/act/profile-*/` | One target per core profile (UDB, Sail configuration and `test_config.yaml`), generated by `tools/riscv_build/gen_profiles.py` |
| `tools/riscv_build/act/sim/test_act.py` | cocotb testbench that watches the HTIF `tohost` word |
| `Insper-RISC-V/` | Submodule with the core, the memories, the peripherals and the simulation tops of the platforms, at the version this repository pins |
| `tools/riscv_build/config.platform-*.yaml` | Configuration of each platform (VHDL sources, top level and memory map), written by `riscv-tools platform sync` from the submodule and never edited by hand |
| `tools/riscv_build/config.yaml` | Extends the `internal-mem` platform and adds the `act:` section (suite and extensions); `config.profile-*.yaml` is the one of each profile without Zifencei, and `config.flash-*.yaml` the one of each profile with Zifencei |

The VHDL comes from the [Insper-RISC-V](https://github.com/insper-riscv/Insper-RISC-V) submodule, which holds the `Core` (the processor), the `Memory` (the memories), the `Peripherals` and the simulation tops of the platforms. The paths in the platform configuration files start with `Insper-RISC-V/`, the folder of the submodule.

## 3. Scope

The certification covers the `I`, `M`, `Zmmul`, `Zicsr`, `Zicntr`, `Zihpm`, `Zifencei`, and `Zicclsm` extensions, listed in `act.extensions` in the configuration. Each of the 60 valid combinations of these extensions over the `I` base, read from the profile matrix of the Core (`profiles/matrix.yaml`), is a core profile with its own target, generated by `tools/riscv_build/gen_profiles.py`; a profile without `Zifencei` runs with `riscv-tools --config tools/riscv_build/config.profile-<name>.yaml certify` on the `internal-mem` platform. The profiles with `Zifencei` need the caches and run on the `de0-cv` platform, with the FLASH behind them, through `tools/riscv_build/config.flash-<name>.yaml`; the `flash-ram-*` targets run the test that rewrites its own code from the SDRAM.

## 4. Running

```bash
git clone --recurse-submodules https://github.com/insper-riscv/Certification.git
cd Certification
uv sync
riscv-tools --config tools/riscv_build/config.yaml certify
```

The tools come from the `ci-act4` image of the [Infra](https://github.com/insper-riscv/Infra) repository: RISC-V GCC, Spike, Sail, GHDL, uv, and Ruby with Bundler and the gems of ACT4's UDB. The full flow is in `.github/workflows/certification.yml`. The run of every profile, with a separate runner per profile, is in `.github/workflows/certification-profiles.yml`; it reads the `tools/riscv_build/config.profile-<name>.yaml` and `tools/riscv_build/config.flash-<name>.yaml` files and, on a manual dispatch, takes a regular expression on the profile name.
